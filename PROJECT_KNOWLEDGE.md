Follow the same discipline the admin-dashboard project used: disclose uncertainty explicitly rather than reporting something as fixed before it's actually confirmed; note dead ends and retracted theories, not just what worked, so a future session doesn't retry them blind.

If a NEW FlutterFlow AI SDK/tooling gotcha is discovered (not specific to this project's own business logic — a DSL quirk, a codegen quirk, a CLI behavior), add it to `.cursor/rules/project_rules.md`'s "FlutterFlow quirks learned the hard way" section instead of (or in addition to) here, so it's visible in the pre-task ritual even for someone skimming only the rules file.

## Relationship to `icoccha-admin-dashboard`

Same overall product family (**Icoccha**, a Japanese paid-companion/concierge booking app), but a **separate FlutterFlow project**, separately bound in this workspace's own `.flutterflow/config.yaml` (`project_id: icoccha-new-mockup-9a6ing`, distinct from `icoccha-admin-dashboard2-3se8y2`). This project is the **guest/cast-facing mobile app** (booking, chat, payments, cast profiles, affiliate); the sister project is the **admin panel** used to operate it.

**Do not assume the two projects share a Firebase backend, Firestore schema, or security rules without checking.** `PROJECT_ANALYSIS.md` §2 notes this project's Firebase project id is `icoccha`, while the admin dashboard's is `icoccha-admin-dashboard` — these may be genuinely separate Firebase projects, or the admin dashboard may be a second FlutterFlow project pointed at the same `icoccha` backend; this hasn't been independently re-verified from this workspace. Confirm the actual live project id/collection shape here before porting any admin-dashboard backend assumption (a Cloud Function name, a collection field, a security rule) across — schema field names, in particular, are already known to diverge (this project has typos like `res_ic` for `res_id` and camelCase `extension_payments` keys that don't match the admin side's conventions; see `PROJECT_ANALYSIS.md` §2 and `IMPLEMENTATION_PLAN.md` §2).

What IS safely shared and already carried over: **FlutterFlow AI SDK/tooling behavior** — the DSL surface, proto quirks, codegen behavior, and CLI mechanics are the same tool regardless of which FlutterFlow project you point it at. That's what `.cursor/rules/project_rules.md`'s inherited quirks section is for.
